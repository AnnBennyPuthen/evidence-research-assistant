# Learning Guide

## File Walkthrough

- `backend/app/models.py`: request, plan, task, source, evidence, claim, report, event, and usage contracts. IDs are generated by application code.
- `backend/app/budget.py`: Quick/Standard hard limits and atomic reservation.
- `backend/app/providers.py`: replaceable OpenAI role adapter and deterministic demo fixtures.
- `backend/app/fetcher.py`: URL checks, streaming size bounds, redirect handling, HTML cleanup, and PDF text extraction.
- `backend/app/graph.py`: `StateGraph`, typed shared state, parallel `Send`, merge reducer overwrite, verification, and report sanitization.
- `backend/app/repository.py` and `runner.py`: SQLite and single-process task lifecycle, cancellation, events, and partial snapshots.
- `backend/app/main.py`: HTTP endpoints, local CORS, status codes, and export responses.
- `frontend/src/api.ts`: the frontend copy of the backend response contract.
- `frontend/src/App.tsx`: the user workflow, polling, claim selection, evidence view, history, and exports.

## Follow One Request

Start in `frontend/src/App.tsx`'s `startResearch`. The browser posts the validated form to the API. `main.py` creates a queued record using `Repository`, then `RunManager` creates one asyncio task. `graph.py` invokes a Pydantic Planner; its plan is dispatched with LangGraph `Send`. Each Researcher receives a distinct task, and `RunBudget` reserves provider calls before use. The merger canonicalizes URLs and passage keys, then Evidence Verifier assessments are clamped to IDs actually present in state. Report Writer returns structured sections; `sanitize_report` drops unsupported claim references and restores exact assessed text for factual findings. The runner stores each node update so cancellation retains partial results. The browser polls events and report state, and clicking a claim filters the passage list by the verifier's evidence IDs.

## Why Four Roles?

The Planner narrows broad questions into independently searchable pieces. The Researcher has only search and inspect tools and works on one assigned piece. Evidence Verifier compares the gathered passages against each candidate and accounts for disagreement, scope, and metadata gaps. Report Writer organizes the result into readable sections without tools. The split creates explicit contracts and inspection points; it does not guarantee correctness. A helper node that deduplicates or persists data is normal deterministic application logic, not an agent.

## Exercises

1. Add one field to `ResearchTask` and update the deterministic demo planner and UI plan view.
2. Write a test for a redirect chain that changes from a public host to a private IPv6 address.
3. Add an explicit “follow-up requested” scenario and route no more than one Quick or two Standard rounds through the same Researcher role.
4. Extend `ClaimAssessment` with optional version/scope notes and display unknown values honestly.
5. Add a PostgreSQL repository implementing the same repository methods without changing graph nodes.
6. Add a reviewed source-independence label and a test showing that identical syndicated text is not counted as independent confirmation.

Run the demo first. It is designed to exercise the actual graph and evidence UI without provider keys or network access. For live mode, store keys in `backend/.env`, use a supported documented model selected with `OPENAI_MODEL`, and remember that provider calls may be billed.
