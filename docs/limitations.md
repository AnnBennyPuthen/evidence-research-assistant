# Limitations And Safety

- **Evidence is not truth.** Statuses mean supported by retrieved evidence, conflicting evidence, or insufficient evidence. Search ranking and extraction can miss important sources. The verifier and semantic report check are fallible; structural reference checks cannot prove entailment.
- **Demo is synthetic.** Its `demo.invalid` references are labels only and are never consulted live. Demo role steps are scripted, and are not live model/search metrics.
- **Independence is approximate.** Canonical URLs and exact content hashes remove some duplicates; near-duplicate detection and syndicated-source independence are not fully implemented. Source counts must not be read as independent confirmation.
- **Metadata may be unknown.** Publication dates and source categories remain unknown unless extracted/reviewed. Official status does not prove accuracy. PDF extraction is text-only, page-limited, and does not OCR scans.
- **Fetching is not a hardened egress proxy.** The app accepts public HTTP(S) destinations only, rejects credentials/local hosts, validates DNS answers and redirects, disables implicit redirects/environment proxies, caps response bytes, and applies TLS verification. DNS is resolved for a precheck but httpx performs the connection lookup separately; DNS rebinding can occur between those operations. A local process/container still shares the host network identity. Use an egress proxy/network namespace with pinned resolution for a public service.
- **No paywall bypass.** The fetcher does not use browser automation, login credentials, OCR, or anti-bot workarounds. Blocked sources remain unavailable.
- **Single process.** Local runs are in-memory asyncio tasks, not a durable distributed queue. Restart marks unfinished jobs interrupted. Cancellation preserves the latest saved graph update, but an in-flight remote request may still finish or incur cost. Multiple app processes are not supported.
- **SQLite is local convenience.** There is no multi-user authentication, retention scheduler, encryption-at-rest layer, or PostgreSQL migration in this version.
- **Live cost and usage are incomplete.** Request counts are bounded. Token usage is shown only where the selected provider integration returns it; absent values are unknown, not zero. No cost estimate is calculated. Configure and check current provider pricing independently.
- **No live-provider validation was run during implementation.** Automated validation uses demo and mocked behavior to avoid paid calls. Live adapter behavior still needs an authorized manual smoke test with current credentials and model availability.
- **Local single-user scope only.** Public deployment would require authentication, rate limiting, durable workers, operational monitoring, reviewed CORS/egress, privacy and retention decisions, and a security review.
